# সিংচাপইড় ইসলামিয়া আলিম মাদ্রাসা — ওয়েবসাইট ও অ্যাডমিন পোর্টাল
**Singchapair Islamia Alim Madrasha — Website & Admin Portal**

প্রথম শ্রেণি থেকে আলিম পর্যন্ত মাদ্রাসার জন্য সম্পূর্ণ ওয়েবসাইট, নিজস্ব ব্যাকএন্ডসহ (PHP + SQLite)। যেকোনো সাধারণ cPanel হোস্টিং-এ ফাইল আপলোড করলেই চলে — আলাদা ডাটাবেস সেটআপ বা build লাগে না।

## 🖥️ নিজস্ব ব্যাকএন্ড (সুপারিশকৃত)

ওয়েবসাইটের সাথে নিজস্ব সার্ভার/ব্যাকএন্ড (`api/` ফোল্ডার, **PHP + SQLite**) দেওয়া আছে। কোনো Firebase বা বাইরের সেবা লাগে না — সব তথ্য আপনার নিজের হোস্টিং-এ থাকে।

| মোড | কখন চালু হয় | তথ্য কোথায় থাকে |
|---|---|---|
| **লাইভ (নিজস্ব সার্ভার)** | PHP সাপোর্টেড হোস্টিং-এ আপলোড করলে — স্বয়ংক্রিয়ভাবে | আপনার সার্ভারের ডাটাবেসে — সবাই দেখতে পাবে ✅ |
| **ডেমো মোড** | GitHub Pages-এর মতো শুধু-স্ট্যাটিক হোস্টিং-এ | শুধু ওই ব্রাউজারে — শুধু দেখার/পরীক্ষার জন্য |
| **Firebase** (ঐচ্ছিক) | `config.js`-এ Firebase বসালে | Google Firebase-এ |

> ⚠️ **GitHub Pages-এ PHP চলে না।** তাই সেখানে সাইটটি শুধু ডেমো মোডে চলবে। সত্যিকারের ওয়েবসাইটের জন্য PHP হোস্টিং লাগবে।

### হোস্টিং-এ ইনস্টল (cPanel, ~১০ মিনিট)
**প্রয়োজন:** PHP **8.1 বা নতুন** (pdo_sqlite সহ — প্রায় সব হোস্টিং-এ থাকে)। বাংলাদেশের যেকোনো সাধারণ cPanel শেয়ার্ড হোস্টিং যথেষ্ট।

1. ডোমেইন ও হোস্টিং কিনুন (যেমন `singchapairmadrasha.edu.bd` বা `.com`)। cPanel → **Select PHP Version** থেকে PHP 8.1+ বেছে নিন।
2. cPanel → **File Manager** → `public_html` ফোল্ডারে এই রিপোজিটরির **সব ফাইল ও ফোল্ডার** আপলোড করুন (`api/` ফোল্ডারসহ; `.htaccess` ফাইলগুলোও যেন যায় — File Manager-এ *Show Hidden Files* চালু করুন)। ZIP আপলোড করে *Extract* করাই সহজ।
3. `api/data` ও `api/uploads` ফোল্ডারে লেখার অনুমতি থাকতে হবে (সাধারণত আগে থেকেই থাকে; না থাকলে Permissions → `755`)।
4. ব্রাউজারে `https://আপনার-ডোমেইন/admin.html` খুলুন → **প্রথমবার সেটআপ** পাতা আসবে → নাম, ইউজারনেম ও পাসওয়ার্ড (কমপক্ষে ৮ অক্ষর) দিয়ে প্রধান অ্যাডমিন অ্যাকাউন্ট তৈরি করুন।
5. **সেটিংস** থেকে প্রতিষ্ঠানের সঠিক তথ্য (EIIN, ঠিকানা, ফোন, অধ্যক্ষের নাম ও ছবি) দিন। অন্য শিক্ষকদের জন্য সেটিংস → **অ্যাডমিন ব্যবহারকারী** থেকে আলাদা অ্যাকাউন্ট দিন।
6. cPanel → **SSL/TLS Status** থেকে ফ্রি SSL (https) চালু করুন।

### অ্যাডমিন লগইন
- ইউজারনেম ও পাসওয়ার্ড আপনি নিজেই প্রথমবার সেটআপে তৈরি করবেন — কোনো ডিফল্ট পাসওয়ার্ড নেই।
- অন্য অ্যাডমিন যোগ, মুছে ফেলা বা পাসওয়ার্ড রিসেট: সেটিংস → অ্যাডমিন ব্যবহারকারী।
- **সব অ্যাডমিনের পাসওয়ার্ড ভুলে গেলে:** File Manager-এ `api/data/` ফোল্ডারে `allow-setup.txt` নামে একটি খালি ফাইল তৈরি করুন, তারপর `admin.html` খুলুন — সেটআপ পাতা আবার আসবে। একই ইউজারনেম দিলে তার পাসওয়ার্ড নতুন করে সেট হবে। কাজ শেষে ফাইলটি স্বয়ংক্রিয়ভাবে মুছে যায়।
- ৮ বার ভুল পাসওয়ার্ড দিলে ১৫ মিনিটের জন্য লগইন বন্ধ থাকে।

### ব্যাকআপ
- অ্যাডমিন → **ব্যাকআপ** থেকে নিয়মিত JSON ব্যাকআপ ডাউনলোড করুন।
- সম্পূর্ণ ব্যাকআপের জন্য cPanel থেকে `api/data/` (ডাটাবেস) ও `api/uploads/` (আপলোড করা ফাইল) ফোল্ডার ডাউনলোড করে রাখুন।
- শিক্ষক/কর্মচারীর তথ্য ছকের গোপন ডকুমেন্ট (NID, নিয়োগ পত্র ইত্যাদির স্ক্যান) `api/data/private/` ফোল্ডারে থাকে — এগুলো JSON ব্যাকআপে আসে না, তাই `api/data/` ফোল্ডারটি অবশ্যই আলাদা করে ব্যাকআপ রাখুন।
- ডেমো মোডে কাজ করা তথ্য সার্ভারে নিতে: ডেমোতে ব্যাকআপ ডাউনলোড → সার্ভারে লগইন করে **ব্যাকআপ → পুনরুদ্ধার**।

### উন্নত সেটিংস (`api/config.php`)
- ডাটাবেস ফাইল `public_html`-এর বাইরে রাখতে বা **MySQL** ব্যবহার করতে `dsn` পরিবর্তন করুন।
- আপলোড সীমা (`max_upload_mb`) ও অনুমোদিত ফাইলের ধরন পরিবর্তন করা যায়। বড় ফাইলের জন্য হোস্টিং-এর PHP `upload_max_filesize`-ও বাড়াতে হতে পারে।
- **Nginx** সার্ভারে `.htaccess` কাজ করে না — `api/data/` ও `api/config.php`-এ সরাসরি প্রবেশ বন্ধ করে দিন এবং `api/uploads/`-এ PHP চালানো বন্ধ রাখুন।

### লোকালি চালাতে
```bash
php -S localhost:8000      # ব্যাকএন্ডসহ (লাইভ মোড)
python3 -m http.server 8000  # শুধু স্ট্যাটিক (ডেমো মোড)
```
তারপর http://localhost:8000 খুলুন (ফাইল ডাবল-ক্লিক করে খুললে কাজ করবে না)।

### ডেমো মোড
GitHub Pages বা অন্য স্ট্যাটিক হোস্টিং-এ সাইটটি ডেমো মোডে চলে। অ্যাডমিন পাসওয়ার্ড **`admin123`** (ইউজারনেম লাগে না)। নমুনা নোটিশ ও একটি নমুনা ফলাফল (চলতি বছর, বার্ষিক পরীক্ষা, ষষ্ঠ শ্রেণি, রোল ১) দেওয়া থাকে।

<details><summary><b>ঐচ্ছিক: Firebase ব্যবহার করতে চাইলে</b></summary>

নিজস্ব সার্ভার না থাকলে Google Firebase-ও ব্যবহার করা যায়:
1. https://console.firebase.google.com → নতুন প্রজেক্ট → **Web** অ্যাপ যোগ করে `firebaseConfig` কপি করে `assets/js/config.js`-এর `FIREBASE` অংশে বসান।
2. **Authentication → Email/Password** চালু করে অ্যাডমিন ইউজার তৈরি করুন; তার **UID** কপি করুন।
3. **Firestore Database** তৈরি করে Rules-এ `firestore.rules` পেস্ট করে Publish করুন। `users` কালেকশনে Document ID = UID, ফিল্ড `role` = `admin`।
4. (ঐচ্ছিক) **Storage** চালু করে `storage.rules` Publish করুন।
5. Authentication → Settings → Authorized domains-এ আপনার ডোমেইন যোগ করুন। লগইন হবে ইমেইল ও পাসওয়ার্ড দিয়ে।
</details>

## 📊 ফলাফল কীভাবে কাজ করে
- গ্রেডিং: ৮০+ A+ (৫.০০), ৭০+ A (৪.০০), ৬০+ A- (৩.৫০), ৫০+ B (৩.০০), ৪০+ C (২.০০), ৩৩+ D (১.০০), ৩৩-এর কম F।
- জিপিএ = সকল বিষয়ের গ্রেড পয়েন্টের গড়; কোনো বিষয়ে F হলে জিপিএ ০.০০ ও অনুত্তীর্ণ। (৪র্থ/ঐচ্ছিক বিষয়ের বোনাস হিসাব অন্তর্ভুক্ত নয়।)
- প্রতিটি ফলাফলের আইডি `সাল_পরীক্ষা_শ্রেণি_রোল` — তাই দর্শক শুধু নির্দিষ্ট রোলের **প্রকাশিত** ফলাফল দেখতে পারে; সবার ফলাফলের তালিকা দেখা যায় না।
- মেধাস্থান: উত্তীর্ণ → জিপিএ → মোট নম্বর অনুযায়ী।

## 🔒 নিরাপত্তা
- পাসওয়ার্ড নিরাপদ হ্যাশ (bcrypt) করে রাখা হয়; লগইন সেশন HttpOnly কুকিতে, প্রতিটি অ্যাডমিন কাজে CSRF টোকেন যাচাই হয়।
- প্রথম অ্যাডমিন তৈরির পর ওয়েবসাইট থেকে আর কেউ সেটআপ চালাতে বা নিজেকে অ্যাডমিন বানাতে পারবে না।
- দর্শকরা শুধু **প্রকাশিত** নোটিশ/ছবি/ফলাফল দেখতে পারে। ফলাফল শুধু নির্দিষ্ট রোল দিয়ে খোঁজা যায় — সবার ফলাফলের তালিকা দেখা যায় না।
- শিক্ষার্থী তালিকা ও ভর্তি আবেদনের তালিকা শুধু অ্যাডমিন দেখতে পারে। ট্র্যাকিং আইডি দিয়ে শুধু নাম, শ্রেণি ও অবস্থা দেখা যায়।
- ভর্তি আবেদন ও বার্তা ফরমে স্প্যাম ঠেকাতে প্রতি ঘণ্টায় সীমা আছে।
- ডাটাবেস ফোল্ডার ওয়েব থেকে বন্ধ (`.htaccess`), আপলোড ফোল্ডারে স্ক্রিপ্ট চলে না।
- নিয়মিত ব্যাকআপ নিন। শিক্ষার্থী/অভিভাবকের ব্যক্তিগত তথ্য পাবলিক নোটিশে প্রকাশ করবেন না।
